# TikoOS v0.1

Рабочий исходный прототип для семейства **LilyGO T-Embed CC1101**, ESP32-S3,
16 MB Flash / 8 MB PSRAM. Собранный app-image находится в `dist/firmware.bin`.
Прототип компилируется; физическая плата в этой сессии недоступна.
**Поведение оборудования и установка через Launcher — Unverified.**

## Возможности

- Графитовый интерфейс 320×170: карточки, cyan/blue/purple акцент, status bar,
  переход с изменением яркости за 160 ms. Отрисовка через TFT_eSPI и RGB565 sprite.
- Notes и Formulas: реальные каталоги/файлы на microSD, категории из директорий,
  UTF-8, кириллица, математика, три размера шрифта, перенос по ширине.
  Чтение блоками 768 байт с сохранением границ UTF-8; число страниц не ограничено
  размером RAM. Позиция страницы и строки записывается при закрытии документа.
- Favorites: до 24 путей в NVS, добавление/удаление из меню читателя,
  удалённые документы помечаются `[нет]`; нажатие предлагает убрать ссылку.
- Files: просмотр всей SD, размеры, TXT-читатель; удаление **файлов** только
  внутри `/TikoOS`, после отдельного подтверждения. Форматирования карты нет.
- Wi-Fi Transfer: локальная WPA2-PSK AP `TikoOS`, случайный пароль на каждый запуск,
  один клиент. Мобильный WebUI: каталоги, TXT upload, просмотр, создание папок,
  подтверждаемое удаление, свободное место. Basic Auth + CSRF header для записи.
  Запись ограничена `/TikoOS`; traversal и некорректные имена отклоняются;
  upload до 2 MiB через временный файл, без перезаписи существующего файла.
  Выход выключает AP. Логин WebUI `tiko`, пароль совпадает с показанным паролем AP.
- Calculator: ввод символов энкодером, десятичные числа, + − × ÷, вычисление слева
  направо, стирание, очистка, проверка деления на ноль/переполнения.
- Stopwatch: старт, пауза, сброс; продолжает считать при выходе из экрана.
- System Monitor / Device Info: heap, PSRAM, flash, CPU, uptime, SD, I2C ACK.
  Процент батареи **Unknown**, без выдуманного значения.
- Настройки NVS: яркость, шрифт, акцент, направление/чувствительность энкодера,
  timeout экрана, переходы, запуск AP с новым паролем. Reset затрагивает только
  настройки, не файлы, избранное или позиции чтения.
- Энкодер: quadrature state table, полный цикл на шаг, отмена дребезга обратными
  переходами, счётчик недопустимых переходов, без ускорения. Кнопки debounce 25 ms.

## Управление

Вращение — выбор/строка текста; нажатие энкодера — открыть/применить.
В читателе нажатие открывает меню избранного, размера шрифта и удаления.
GPIO6 — Back; удержание энкодера 650 ms — Back. В Files удержание на файле
открывает удаление; для не-TXT это меню открывается обычным нажатием.
GPIO0 также является BOOT: не удерживайте его при включении, кроме USB recovery.
После timeout первое действие только будит экран.

Calculator: вращением выберите символ, нажатием введите; `=` вычисляет,
`C` очищает, `<` стирает символ. Отрицательное число можно получить через `0 - n`.
В Stopwatch вращением выберите Старт/Пауза или Сброс.

## Сборка на CachyOS / Arch Linux

```sh
sudo pacman -S --needed python python-pip git base-devel
python -m venv .venv
. .venv/bin/activate
pip install platformio==6.1.18
pio run -e tiko -j 4
```

Пины фиксированы в `platformio.ini`; определение платы — `boards/tiko-cc1101.json`.
Платформа espressif32 6.13.0, Arduino ESP32 2.0.17, C++17; TFT_eSPI закреплён
по commit версии 2.5.33. LVGL не используется: собственный лёгкий renderer имеет
кириллический набор, не зависящий от SD. Для пересоздания шрифтов нужен Pillow
13.0.0 и DejaVu Sans (в Arch пакет `ttf-dejavu`); `python scripts/generate_fonts.py`.
Готовые glyphs включены в репозиторий, лицензия — `assets/FONT-LICENSE.txt`.

В облачной среде реестр PlatformIO был недоступен (proxy 403). Успешная сборка
выполнена тем же PlatformIO builder с официальными архивами Espressif из GitHub,
проверенными по SHA-256 из официального Arduino package index. SCons и esptool
установлены через PyPI. Воспроизводимый обход зависимости от реестра:

```sh
python3 -m venv /workspace/pio-venv
/workspace/pio-venv/bin/pip install -r scripts/requirements-cloud.txt
/workspace/pio-venv/bin/python scripts/bootstrap_cloud.py
/workspace/pio-venv/bin/python scripts/cloud_pio.py run -c /workspace/tiko-cloud.ini -j 4
```

Эти команды рассчитаны на Linux x86_64 и рабочий каталог проекта. Все вспомогательные
инструменты размещаются в `/workspace`, `platformio.ini` не переписывается.
TLS и контрольные суммы не отключаются. Обычный `pio run` требует доступа к реестру.
Сведения о сборке и ограничениях — `BUILD.md`, аппаратный чек-лист — `TESTING.md`.

## microSD

FAT32, MBR. Скопируйте каталог `sdcard/TikoOS` в корень microSD, сохранив чужие
файлы и существующие пользовательские документы. Не форматируйте карту ради
установки. В `dist/TikoOS-v0.1-sd.zip` также включён app `firmware.bin` для Launcher.

Пример пути: `/TikoOS/notes/Physics/Heat.txt`. Формулы — `/TikoOS/formulas/<предмет>/*.txt`.
Каталоги `favorites`, `config`, `assets` зарезервированы; избранное/настройки
в v0.1 хранятся в NVS. Без карты или пакета приложение показывает отсутствие данных.

## Launcher: установка app-image

1. Сначала прочитайте `docs/HARDWARE.md`: надпись Plus сама по себе не подтверждает
   совместимость конкретной ревизии. Сверьте разводку с вашей платой.
2. Сохраните резервные копии SD и Launcher/data partitions средствами Launcher.
3. Скопируйте **`dist/firmware.bin`** на SD. Это app-image, не merged/factory image.
4. В Launcher: `SD` → файл → `Install`. Проверьте, что распознан ESP32-S3 и
   выбран свободный подходящий app-раздел, вмещающий весь файл (размер в BUILD.md).
   Не подтверждайте операцию, которая удаляет Launcher, bootloader или нужные данные.
5. Запустите установленное приложение. Проверьте дисплей, GPIO6, SD и энкодер.

`partitions.csv` служит для сборки/отдельной USB-установки и **не поставляется для
перезаписи таблицы Launcher**. Программа не вызывает OTA repartition/erase/USB upload.
Использует существующий NVS namespace `tiko-v1`; требуется обычный NVS-раздел
и ESP32-S3 Arduino bootloader с совместимыми параметрами flash/PSRAM.
Размер app сам по себе не доказывает совместимость текущей таблицы разделов.
Статически проверить реальную таблицу вашей платы и наличие Launcher невозможно.

## Восстановление USB

Если приложение не отвечает, сначала попробуйте вернуться в Launcher его штатным
способом загрузки (для CC1101 Launcher использует GPIO6 при старте; сверить версию).
Если это не работает: подключите USB data-кабель, удерживайте BOOT/энкодер GPIO0,
нажмите RESET или переподключите питание, отпустите BOOT после появления USB device.
На Linux проверьте `ls /dev/ttyACM*`, при необходимости права `uucp`/`dialout`.
Используйте официальный образ/инструкцию восстановления **Launcher для вашей платы**.
Не применяйте произвольные offsets; текущий app не заменяет bootloader/Launcher.
`esptool --chip esp32s3 --port /dev/ttyACM0 chip_id` — только чтение идентификатора.
Команды erase_flash и автоматическая прошивка в проект не включены.

## Ограничения прототипа

- Аппаратное тестирование не выполнялось. Имя Plus не подтверждено отдельной board
  definition в изученном LilyGO checkout; поддержка привязана к опубликованным пинам.
- Нет плавного пиксельного скроллинга: текст перемещается строками; переход — fade,
  а не LVGL animation. Длинное слово переносится по glyph, не по словарю.
- WebServer синхронный: большой upload/view может временно задержать UI. Энкодер
  продолжает считать переходы в ISR, но длительные нажатия могут быть пропущены.
  Нет заявления о полностью неблокирующем сетевом UI.
- До 128 видимых записей на каталог; при превышении показано предупреждение.
  Большие библиотеки разделяйте на подкаталоги. HTTP-список также ограничен 128.
- Последняя позиция сохраняется при закрытии; внезапная потеря питания до закрытия
  возвращает предыдущую сохранённую позицию. Индекс NVS — 32-bit hash пути;
  теоретические коллизии не исключены.
- I2C ACK показывает присутствие адреса, не полноценный тест PN532/PMIC.
  CC1101/nRF24 не опрашиваются: нет непроверенных register writes, передачи RF,
  IR, BLE или RGB-эффектов. Расширение аппаратных драйверов — отдельная работа.
- Карта должна оставаться вставленной: hot swap не поддержан; при ошибках носителя
  завершите Wi-Fi Transfer и перезагрузите устройство. FAT rename не гарантирует
  атомарность при потере питания. Возможен оставшийся скрытый `.upload-*` файл.
- Шрифт содержит латиницу, всю русскую кириллицу и выбранные символы математики;
  отсутствующий glyph заменяется U+FFFD. Markdown/LaTeX не интерпретируются.
